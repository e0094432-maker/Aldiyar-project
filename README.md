# EduForge Advisory — сайт

Скелет сайта-визитки по ТЗ «Сайт_EduForge_структура_и_тексты_v2».
Задача сайта — объяснить, что компания помогает открыть филиал зарубежного вуза
в Казахстане, и получить заявку («Обсудить проект»). Языки: RU / EN / KK.

**Хостинг:** Vercel (бесплатный план Hobby, автодеплой из ветки `claude/new-session-h6mm0x`).
Старый адрес на Render (https://eduforge-8v0r.onrender.com) приостановлен — у workspace закончились бесплатные часы.

## Стек

- **Next.js 16** (App Router, Cache Components) + React 19 + TypeScript
- **Tailwind CSS v4** — дизайн-токены в `src/app/globals.css`
- **nodemailer** — отправка заявок на почту и автоответ клиенту
- **zod** — проверка заявки на сервере
- Шрифт **Manrope** подключён локально (`@fontsource-variable/manrope`), есть все казахские буквы

## Запуск

```bash
npm install
cp .env.example .env.local   # заполнить SMTP, если нужно слать письма
npm run dev                  # http://localhost:3000 → редирект на /ru
```

Другие команды: `npm run build`, `npm start`, `npm run lint`, `npm run typecheck`, `npm run format`.

| ----------------------------- | ------------------------------------------------------------------------------------------------- |
| `/ru`, `/en`, `/kk`           | Главная: 10 блоков по ТЗ, меню шапки ведёт к блокам по якорям                                     |

Адреса без языка (`/`, `/contacts`) перенаправляются на язык из cookie выбора или браузера,
по умолчанию — русский (`src/proxy.ts`). Есть `sitemap.xml` с hreflang и `robots.txt`.

Плюс круглая кнопка WhatsApp в углу на всех страницах. На телефоне — одна колонка и бургер-меню.

## Где что менять

```
src/
├─ content/
│  ├─ dictionaries/ru.ts, en.ts, kk.ts   ← все тексты сайта (типизированы: types.ts)
│  └─ services.ts                        ← список и порядок услуг, иконки
├─ config/site.ts                        ← телефон, email, WhatsApp, Telegram, карта 2ГИС
├─ app/
│  ├─ globals.css                        ← цвета, шрифт, радиусы (дизайн-токены)
│  ├─ [lang]/…                           ← страницы
│  └─ api/lead/route.ts                  ← приём заявки
├─ components/
│  ├─ layout/                            ← шапка, подвал, переключатель языка, кнопка WhatsApp
│  ├─ sections/                          ← блоки страниц (Hero, Services, Faq, LeadForm, …)
│  └─ ui/                                ← кнопки, иконки, заголовки секций
├─ lib/                                  ← схема заявки, отправка писем, SEO
└─ proxy.ts                              ← редирект на язык, 404 для неизвестных услуг
```

- **Тексты в [квадратных скобках]** — как в ТЗ, это данные, которые нужно подтвердить.
  На сайте они подсвечены жёлтым. Убрали скобки в словаре — подсветка исчезла.
- Если в `en.ts`/`kk.ts` не хватает ключа, TypeScript не даст собрать проект.

## Форма заявки

Форма отправляет JSON на `POST /api/lead`. Сервер проверяет поля, отсекает ботов
(скрытое поле + лимит 5 заявок с IP за 10 минут), отправляет письмо менеджеру
(на русском, `Reply-To` = email клиента) и автоответ клиенту на его языке.
После успеха — переход на «Спасибо за заявку».

Если `SMTP_HOST` не задан, заявка просто пишется в лог сервера — удобно для разработки.
Переменные — в `.env.example`.

## Что нужно подтвердить у клиента

- Телефон, email, WhatsApp, Telegram — `src/config/site.ts`
- «Первая встреча — [бесплатно]», срок ответа «[1 рабочего дня]», часы «[9:00–18:00]»
- Реквизиты (ТОО, БИН, IBAN, банк, БИК)
- Логотип (сейчас временный знак-арка)
- Виджет карты 2ГИС — вставить URL в `site.map.embedUrl`
- Политика конфиденциальности — сейчас черновик-шаблон

### Нестыковки в ТЗ

- В разделе 3 «Услуги (3 карточки)», а на схеме и в модулях — 4 карточки, страниц услуг × 4.
  Сделано 4; тексты карточки **«Финализация соглашения»** — черновик.
- Карточки **«Для кого»** есть на схеме и в модулях, но текстов нет — написан черновик.
- На схеме «…ещё 6 вопросов» (итого 9), а в ТЗ 6 вопросов — выведены 6.
- Содержимое **страниц услуг** (5–6 пунктов, результат, исключения, вопросы) в ТЗ не описано — черновики.
- Переводы **EN и KK** сделаны с русского — нужна вычитка носителями.

## Не сделано в первой версии

- **Админка** (тексты на 3 языках, вопросы, заявки с выгрузкой в Excel, контакты).
  Тексты уже вынесены в словари, а контакты — в один конфиг, поэтому их легко
  перенести в CMS. Вариант: Payload CMS — ставится прямо в этот Next.js-проект,
  поддерживает локализацию полей и экспорт коллекций.
- Хранение заявок в базе (сейчас — только письма).
- Аналитика (Яндекс Метрика / GA).
- По ТЗ не делаем: команду, отзывы, кейсы, блог.

## Деплой

### Vercel (основной)

vercel.com → Sign up with GitHub → **Add New → Project** → импортировать `Aldiyar-project` → **Deploy**.
Настраивать ничего не нужно: адрес сайта для canonical/sitemap берётся из `VERCEL_PROJECT_PRODUCTION_URL`.
Для своего домена задать `NEXT_PUBLIC_SITE_URL`, для писем — SMTP-переменные из `.env.example`.
Free-план Vercel не «засыпает» и предназначен для некоммерческих проектов — для боевого сайта нужен Pro.

### Render (запасной)

Был — **Render** (Free, Frankfurt): build `npm ci && npm run build`, start `npm start`,
переменные `NODE_VERSION=22`, `NEXT_PUBLIC_SITE_URL`. Для писем добавить SMTP-переменные из `.env.example`.

Подходит и любой другой хостинг с Node.js (Vercel, VPS, Docker).

### Чтобы бесплатный Render не засыпал

Free-инстанс засыпает после 15 минут без запросов (первое открытие потом ~30–60 с).
Для мониторинга есть лёгкий эндпоинт `GET /api/health` → `{"ok":true}`.

UptimeRobot → **New monitor** → тип **HTTP(s)** → URL
`https://eduforge-8v0r.onrender.com/api/health` → интервал **5 минут** → Create.

⚠️ На Free у Render **750 часов в месяц на весь workspace**. Один сервис, который не спит,
съедает ~744 часа — остальным бесплатным сервисам в этом workspace почти ничего не останется.
Для постоянной работы лучше план Starter для этого сервиса.
